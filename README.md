# 飞书桥接Codex

macOS Apple 芯片与 Windows 10+ x64 桌面程序。飞书消息经允许名单筛选后交给本机 Codex App Server，结果回到原飞书会话的运行卡片。

## 使用

1. Mac 安装 DMG；Windows 运行 EXE，按安装向导完成安装后从开始菜单启动。在“设置”填写飞书 App ID、App Secret、允许使用的成员 `open_id`，并选择 Codex 模型、推理强度和会话空闲超时。默认使用 `gpt-6-sol`、`max` 和 24 小时。
2. 如需群聊，开启“处理群聊 @ 消息”，并逐行填写允许使用的群聊会话 ID（`oc_...`）。名单外的群聊始终不能使用。
3. 保存设置后，在“总览”手动启动桥接。两个自启动开关分别控制登录电脑时打开客户端、客户端启动后自动连接；默认都关闭。
4. Mac 可在“设置 → 启动方式”开启“隐藏程序坞图标”，默认关闭。保存后立即生效，重启后保留；关闭开关并保存即可恢复程序坞图标。开启后通过右上角菜单栏图标显示窗口，关闭窗口仍继续后台运行。Windows 点击窗口关闭按钮时，可选择“最小化到托盘”继续后台运行，或选择“关闭工具”退出；托盘图标可恢复窗口。

App Secret 通过 stdin 交给固定名称 `bridge` 的飞书 CLI profile，不写入本程序的设置文件或日志。Codex 子进程沿用当前用户的 Codex 登录态与技能配置；客户端只管理自己启动的子进程。

模型和可选推理强度由 Codex 实时返回，列表只显示模型名称。桥接固定使用完全访问和无需审批；允许名单成员发起的任务可直接操作本机文件及网络。会话超过所设小时数未活动后，下一条消息会新建 Codex 会话，旧会话仍保留。Codex 执行时仍需工作目录：已有配置继续沿用原目录，新安装默认使用用户主目录。

飞书控制指令（群聊仍需 @ 机器人）：

| 指令及别名 | 操作 |
| --- | --- |
| `/新建会话`、`/会话` | 点卡片确认，仅新建当前聊天中你的 Codex 会话；还有执行或排队任务时提示处理完后重试。 |
| `/切换模型`、`/切模型`、`/换模型` | 单列全宽按钮，每页最多 50 个模型，更多时分页。修改工具全局设置，换模型后各聊天下一条新收到的消息新建会话。 |
| `/推理强度`、`/强度`、`/推理` | 选择当前模型支持的强度。修改工具全局设置，之后收到的消息生效，继续原会话。 |
| `/取消` | 取消尚未提交的菜单操作，不停止 Codex 任务。 |

菜单都有取消按钮，5 分钟后自动失效；发送普通消息会退出菜单并正常处理任务，新指令替换旧菜单。点选提交后显示处理结果，重复或已失效按钮不会再生效。模型及强度保存后同步桌面设置，重启仍保留；正在执行及已经排队的任务继续使用原设置。新模型不支持原强度时采用新模型的默认强度。

## 构建

在 macOS 上出包，需要 Node.js、npm、`curl` 和 `tar`。Apple 芯片还需安装 Rosetta 2（`softwareupdate --install-rosetta --agree-to-license`），用于运行 electron-builder 内置的 x86_64 `mac/makensis`；Windows EXE 使用这套完整的 NSIS 工具。先安装依赖，再双击项目根目录的 `一键打包.command`；命令行也可运行：

```sh
npm ci
npm run package:release
```

每次成功出包只增加一次补丁版本，例如 `1.0.7` 生成 `1.0.8`。两个成品分别为 `release/<版本>/飞书桥接Codex-<版本>-mac-arm64.dmg` 和 `release/<版本>/飞书桥接Codex-<版本>-win-x64.exe`；失败时版本不变。Windows EXE 是带安装向导的安装包。包内固定 Codex CLI 0.158.0 与官方 lark-cli 1.0.72，并附许可证。DMG 未使用开发者签名或公证；Windows EXE 未签名。

Windows 验收：运行 EXE 并完成安装，从开始菜单启动客户端；启动桥接；点击关闭按钮并选择最小化，确认托盘可恢复且桥接仍运行；再次关闭并选择关闭工具，确认托盘图标和后台进程退出。如客户端启动失败，会弹出原因，详细记录保存在用户数据目录的 `bridge.log`。

`npm run build` 只编译代码，不启动桥接或连接飞书。`npm run start` 用于本机开发，默认不自动连接。
